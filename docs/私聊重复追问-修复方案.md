# 私聊重复追问问题 · 修复方案

> 本文是《鲸鲸私聊问题分析》的落地实施方案。已去除所有身份信息（wxid、昵称、会话目录、时间戳），只保留行为机制与代码路径。

## 一、现象（脱敏）

1. **反复追问同一件事**：同一件「未兑现的小事」（如一次没补发的语音），在同一天里被换了多种说法反复提起，即使对方已经兑现、或明确转移话题，鲸鲸仍会再问。
2. **多轮对话里角色归属翻转**：对方说「帮我挑 X」，两三轮后鲸鲸把「帮谁挑」的主语弄反，认定成对方自己要。
3. **被指出「你刚问过」后才意识到**，说明缺少「我是不是刚问过」的自检。

## 二、根因（5 + 1）

| # | 根因 | 代码依据 |
|---|------|---------|
| 1 | 未兑现事项 = 每轮常驻背景，无生命周期；`mentions` 计数有但没交给模型 | `episode.js` 只 `addThread` 不 `closeThread`；`format.js` 只输出正文不输出计数 |
| 2 | 私聊缺「别重复问」规则（`GROUP_HISTORY_RULE` 只给群聊），私聊「别装失忆」方向相反 | `persona/index.js` 716 / 766 行 |
| 3 | 防复读只认字面重合，换说法全放行 | `core/echo.js` |
| 4 | 抽取器只增不关，错误理解被固化成事实 | `memory/episode.js`、`memory/extractor.js` |
| 5 | 模型配置放大：无思考 + 高温 + 大预算 | `config.json`（用户侧） |
| 次生 | 角色归属翻转：缺「分清主语」规则 | `persona/index.js` 对话理解段 |

## 三、解决方案

### P0 · 止血（本轮实施）

**P0-1 · 记忆渲染加「提过几次」信号**（`src/memory/format.js`）
- 渲染「偏好 / 没聊完」时，对 `mentions >= 3` 的条目追加 `（已提 N 次）`。
- 让系统早就记录、但一直没交给模型的计数，真正进提示词——模型看到「已提 101 次」就知道该收手。

**P0-2 · 私聊补「别重复问」规则**（`src/persona/index.js`）
- `privateSceneStaticLines` 增加一条：同一件事刚聊过 / 今天提过就别再主动追问；被指出「你刚问过」就顺着承认。

**P0-3 · 预算不再放大「没聊完」**（`src/memory/budgetPlan.js`）
- `cardCaps()` 里 `threads` 固定为基准值（4），不随 `dialogueBudget` 等比放大，避免「未兑现事项」被顶到必现位置。

### P1 · 根治（后续）

- **P1-1 线程生命周期**：抽取器输出「已解决 / 已兑现」项，据此 `closeThread` + `supersedeFact`；`addThread` 前做文本相似度去重，同一件事不抽成多条。
- **P1-2 话题级去重**：在字面 echo 之外，对「主动重提同一主题词」做去重，拦换说法重复。

### P2 · 增强（后续）

- **P2-1 主语归属规则**：对话理解段加「分清每句话主语、谁让谁做什么」。
- **P2-2 抽取器对齐原文**：抽取事实要求对齐原文消息、主语归属明确。
- **P2-3 配置建议**：`temperature` 降到 0.7、开 `thinking`、`dialogueBudget` 降到 5500~7000（用户侧可调，不硬编码）。

## 四、验证

- 修完 P0 后：查记忆卡，验证「未兑现事项」的 `mentions` 不再无意义增长；行为回归「刚聊过的事不再换说法反复问」。
- 全量测试 + `check-layers` + `release-check` + `privacy-scan` 通过后提交。
