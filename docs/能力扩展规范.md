# 能力扩展规范（后来人必须遵守）

> 一句话：**新增能力 = 往内核注册表加一条**；提示词、聊天内触发、启动器「能力」页子菜单、配额与动作记录都会自动生效。
> 不要为每个能力单独改聊天管线，也不要在启动器里手写一个新页面。

---

## 1. 什么是「能力」

能力 = 鲸鲸可以在聊天里**自己判断要不要做**、并由内核在后台执行的一件事。

例：`bili.watch`（逛 B 站）、`bili.diary.write`（写今天的日记）。

它不是「定时任务」也不是「命令」：定时任务按时间跑，命令固定回复；能力由她在对话里决定。

---

## 2. 目录与数据流

```
聊天提示词 ← capabilities.block()/recentBlock()      （自动：能力清单 + 最近做过）
     ↓
模型回复末尾写 [[cap:<id>]]
     ↓
src/pipeline/chat.js：detect → strip（标记不发给对方）
     ↓ 先回复，后执行
src/services/capabilities.js run()：开关/配额/执行/记录
     ↓
data/caps/actions.json（结果）→ 下一轮 recentBlock 让她「记得自己做过」
     ↓
启动器「能力」页 ← /api/capabilities（自动一项一个子菜单）
```

---

## 3. 新增一个能力（checklist）

1. **注册表**：在 `src/services/capabilities.js` 的 `REGISTRY` 里加一条：

```js
{
  id: 'bili.share.today',              // 必须 <domain>.<action>，小写，稳定，不复用
  label: '分享今天的视频',              // 子菜单标题，≤8 字
  desc: '把今天看过最好的一条发到私聊',  // 一句话说明 + 副作用必须写出来
  enabled: (config) => features.isOn(config, 'bili'), // 依赖的功能开关（不可用时 UI 置灰）
  async run(runtime, { now }) {
    // 做正事；不要在这里发聊天消息（除非 desc 明确说明且用户预期）
    return { ok: true, summary: '已分享 1 条' }; // 失败返回 {ok:false, summary:'原因'}
  },
}
```

2. **不要改 UI**：启动器「能力」页（`launcher/Views/CapabilitiesPage.cs`）从 `/api/capabilities` 动态生成子菜单，新增能力会自动出现；页面只负责通用的「启用 / 每日上限 / 今日次数 / 最近一次 / 执行一次」。

3. **不要改聊天管线**：`[[cap:<id>]]` 的识别、剥离、异步执行、次数限制、动作记录都是通用逻辑。

4. **配置**：每个能力的开关/额度放 `capabilities.items.<id> = { enabled, maxPerDay? }`，由 `/api/capabilities/set` 写回 `config.json`；全局开关是 `capabilities.enabled` / `capabilities.maxPerDay`。不要在能力代码里另造一套开关。

5. **副作用**：
   - 默认**不主动发消息**；会发消息的能力必须在 `desc` 里明说，并复用现有发送/分享链路（例如 B 站分享的 outbox），不要绕过配额与去重。
   - 文件、网络、模型调用都要 try/catch，`run` 里抛异常会被记为失败，不影响聊天。

6. **测试**（缺一不可）：
   - `tests/capabilities.test.js` 增加：新能力出现在 `list/promptItems`；开关关闭后 `run` 返回不可用；
   - 能力本身的行为要有单测（用临时目录 + 假依赖，不联网）；
   - 跑 `node scripts/check-layers.js`、`privacy-scan.js .`。

7. **文档**：`CHANGELOG.md` 写一段；如果引入新配置字段，补 `configSchema`。

---

## 4. 启动器「能力」页的 UI 约定

- 左侧列表 = 能力子菜单（一项能力一个），标题用 `label`；
- 右侧固定包含：说明（`desc`）、启用开关、每日上限（空 = 跟随全局）、今日次数、最近一次、**现在执行一次**；
- `available=false`（依赖的功能关着）时开关置灰并说明原因；
- 新增能力**不允许**在别的页面另加入口；需要专属配置时，先扩展通用详情字段，而不是复制一个页面。

## 5. 现有能力

| id | 子菜单 | 依赖 | 说明 |
|---|---|---|---|
| `bili.watch` | 逛 B 站 | `features.bili` | 拉推荐、看 2 条、写日记；不主动发分享 |
| `bili.diary.write` | 写今天的日记 | `features.bili` + `bili.diary.enabled` | 用当天聊天素材更新当天那一篇 |

---

## 6. 不做的事

- 不在能力里直接改 `config` 的其他字段（配置只走 `/api/capabilities/set` 或设置页）；
- 不加「能力专用」的定时器；定时任务归调度器，能力只在被触发时执行；
- 不把能力标记透传给对方（`strip` 已处理，别绕开）；
- 不在能力里写聊天正文/图片内容到日志（只记长度、id、结果）。
