# 记忆 · 人设 · 日记 联动方案

> 面向：想让鲸鲸「记得住、长得出、有个性」而不是「三套系统各管各」的人。
> 结论先行：**记忆只记「对方」，人设只写「静态的她」，日记只写「B 站的她」——三者之间缺一个「她自己的长期记忆」做枢纽。**
> 实测依据：`src/memory/*`、`src/persona/*`、`src/services/bili/{diary,weekly,digest,chatDigest}.js`、`docs/记忆系统.md`（2026-11-10）。
>
> **落地状态（2026-11-10）**：P0、P1、P2 全部落地 ——
> - P0：记忆抽取（`extractor.js` 的 `EPISODE_SYSTEM`）注入「鲸鲸的语气是人设、不当成情绪基调」边界；日记/周小结（`diary.js`/`weekly.js`）注入 `persona.voiceHint(config)` 用她的语气写。
> - P1：SelfCard 存储（`src/memory/selfCard.js`，全局一张）+ 周小结写回（`weekly.maybeUpdate` 调 `selfCard.applyWeekly`）。
> - P2：SelfCard 作为「动态人设层」注入聊天（`selfCard.blockFor` → 拼进记忆块）；日记素材 `chatDigest.collectDay` 带上「关于 TA」的人物卡记忆沉淀。
> 至此「记忆→人设、人设→记忆、日记→记忆、日记←记忆」四个方向全部打通。剩下的 schema v2 / 漂移监测 / 调教带证据是另两篇文档里的 P2 级建议。

---

## 一、三者的数据关系与依赖

### 1.1 各自是什么

| 系统 | 存储位置 | 内容 | 更新方式 |
|---|---|---|---|
| **记忆** | `data/memory/chats/<hash>/people/<hash>.json` + `messages.jsonl` | **关于对方**：人物卡（traits/preferences）+ 事件卡 + threads + 摘要 | 规则即时（自述/纠正/记住）+ episode 关闭批量调模型 |
| **人设** | `config/persona` + `data/persona.json` | **静态的她**：名字/年龄/外形/性格/背景 + customPrompt（增量）+ 调教（styleText） | 只靠主人手动改 / 导入预设 |
| **日记** | `data/bili/diary/{owner,self}.md` + `weekly.json` | **B 站的她**：今天看了什么、自我偏好、每周小结 | 看视频/聊天后闲时写，每天重写一篇；每周日压成小结 |

### 1.2 依赖关系（现状）

```
                    config/persona（静态人设 L0）
                           │ 生成
                           ▼
              buildPromptParts ──→ system + 本轮状态
                     ▲                    ▲
                     │                    │
   【记忆】 messages.jsonl ──抽取──→ 人物卡/事件卡 ──检索──→ soft block（尾注入）
                     ▲
                     │  chatDigest.collectDay 读原文（每会话≤6句）
                     │
   【日记】 owner.md / self.md  ←── watched（B站 feed）+ chatDigest
                     │
                     ▼  weekly.maybeUpdate（每周日）
              weekly.json（summary/likes/dislikes/state）
                     │
                     ▼  weekly.blockFor（≤14天有效）
              注入聊天「底色」（尾注入，不持久化）
```

**三条关键依赖**：

1. **记忆 ← 原文**：`extractor.extractEpisode` 从 `messages.jsonl` 抽事实/性格/事件，写进「对方」的人物卡。主语永远是**对方**，不是鲸鲸。
2. **日记 ← 原文 + B站**：`chatDigest.collectDay` 读的是 `store.messages()` 的**原文**（每会话 6 句、共 6 会话），不是人物卡/事件卡；加上 B站 `watched`。
3. **日记 → 聊天**：`weekly.blockFor` 把周小结注入聊天当「底色」，`digest.blockFor` 在被问「今天看了啥」时注入当天摘要。两者都只注入、**不写回任何持久化**。

## 二、割裂与冲突点

### 割裂 1：记忆永远反哺不了人设

`docs/记忆系统.md` 硬约束：「**聊天内容不能写 L0**」。所以「TA 是嘴硬心软」「她总在深夜被逗笑」这些记忆沉淀，**永远进不了她的性格**。她的性格只有两条路：主人手动调 `styleText`，或 B站 weekly「底色」临时注入。

→ 冲突：`weekly.blockFor` 已经是「记忆→语气」的雏形，但它①只来自 B站日记、不来自通用记忆；②只注入聊天、14 天后过期；③不持久化。等于「让她因你而变」这个最值钱的能力，被限定在 B站一个垂直场景里。

### 割裂 2：日记和记忆读的不是同一份数据

- 记忆沉淀的是「**TA 嘴硬心软、正在纠结辞职**」（人物卡 + 事件卡）。
- 日记写「今天聊到 X」时，`chatDigest` 只给**零碎原文**（每会话 6 句），**完全看不到这些沉淀**。

→ 冲突：日记本应是「她回顾今天」的最高质量素材，实际拿到的却是最原始、最没信息量的切面。她写日记时「失忆」了。

### 割裂 3：没有「鲸鲸自己的记忆」

记忆系统只有「对方的人物卡」，**没有「她自己的卡」**。她的观点、状态、喜好（「最近累了」「更喜欢猫视频」）只存在于 `self.md` 和 `weekly.json`，而它们在 `data/bili/` 目录——**记忆系统看不到，人设系统也看不到**。

→ 冲突：出现了两个同名不同义的「偏好」：记忆的 `preferences`（**对方**喜欢猫/不吃香菜）vs 日记的 `likes/dislikes`（**她自己**想看什么）。数据模型层面没有把「她自己」当成一等公民。

### 割裂 4：日记/小结的「声音」不是她

`diary.js` 的 `SYSTEM` 是通用「你在给自己写日记」，`weekly.js` 也是通用「你在整理这一周的日记」，**都没注入她的 persona**。

→ 冲突：同一个角色，聊天里是「有性子/毒舌」，日记里却可能是客服腔。她写出来的日记「不像她」。

### 割裂 5：人设约束不了记忆生成

`extractor.EPISODE_SYSTEM` 是通用「你在整理聊天记录」，不注入人设边界。

→ 冲突：一个「高攻击力贴吧」人设，抽取记忆时用通用提示词，很可能把「互怼」「玩笑」误判成负面 `valence`，把「毒舌」写成「情绪失控」。**记忆的基调和人设的基调对不上。**

## 三、联动方案：引入「鲸鲸的自我卡」做枢纽

核心动作：新增一张 **SelfCard（鲸鲸自己的卡）**，字段沿用人物卡的结构，但主语是她自己。它同时被记忆、人设、日记读写，成为三者唯一的交汇点。

```
                  ┌──────────── 人设 L0（静态）────────────┐
                  │                                        │
                  │  selfCard 作为「动态人设层 L0.5」注入      │
                  │                                        ▼
   【日记】 ──写回──→  SelfCard（她自己的 traits/preferences/events）── 约束 ──→ 【记忆抽取】
                  ▲                                        │
                  │                                        │
                  └────────── 周小结/日记 沉淀 ──────────────┘
```

### 方案 1：让记忆沉淀影响人设塑造（SelfCard 反哺 L0.5）

- **不动 L0**（守住「聊天不能改静态人设」的安全边界）。
- 新增 **SelfCard** 作为「动态人设层」，记录**关于她自己的**：
  - traits：「对主人会更嘴硬」「被夸会得意」这类她自己的性格倾向；
  - preferences：「最近更喜欢接梗」「不喜欢被半夜打扰」；
  - events：「上周主人病了，她担心了一整天」。
- 由**周小结任务**（复用 `weekly.maybeUpdate` 的时机）把「这一周她因谁、因什么而变」沉淀进 SelfCard。
- SelfCard 作为 `L0.5` 注入 system（带 `updatedAt` + 版本，可回滚），让她「越聊越有自己的性子」。

> 现有雏形：`weekly.blockFor` 的「底色」注入 + persona 的 `styleText` 调教。缺的是**持久化的 SelfCard** + **自动沉淀**，而不是临时注入。

### 方案 2：让人设约束记忆生成（记忆抽取注入人设边界）

- `extractor.extractEpisode` 的 `EPISODE_SYSTEM` 里，追加 2~3 句「人设边界」，从 persona 压一句话：
  - 「她平时毒舌/爱互怼，那是她的语气，不是对对方的负面评价；别把玩笑、互怼写成负面 valence；traits 要写对方的稳定性格，不要写她的语气。」
- 成本：抽取是后台任务，不占回复热路径；多 2~3 句几乎无感。
- 收益：`valence`/`traits` 的基调和人设一致，不再「贴吧人设记出一堆负面情绪」。

### 方案 3：让日记反向丰富记忆（写回 SelfCard + 日记读记忆）

- **写回**：`weekly.maybeUpdate` 产出小结时，除了 `weekly.json`，**同时写一条 SelfCard**（likes/dislikes → preferences，state → 事件/thread）。让「她这周累了、更喜欢猫视频」真正持久化，而不是 14 天消失。
- **日记读记忆**：`chatDigest.collectDay` 从「读原文 6 句」改为「读**当天人物卡/事件卡的摘要**」——让日记写「今天」时能看见「TA 正在纠结辞职」这种沉淀，而不是零碎原话。
- **日记用自己的声音写**：`diary.js`/`weekly.js` 的 `SYSTEM` 注入 persona 的语气一句话（「按你平时在微信里的语气写，别变客服腔」），让日记「像她」。

## 四、优先级与实施要点

| 优先级 | 动作 | 对应 | 风险 | 要点 |
|---|---|---|---|---|
| **P0** | 记忆抽取注入人设边界 | 方案 2 | 低 | 改 `extractor.js` 的 `EPISODE_SYSTEM` 组装；后台任务，不占热路径 |
| **P0** | 日记/周小结用她的 voice | 方案 3-③ | 低 | `diary.js`/`weekly.js` 的 `SYSTEM` 加一句「按人设语气」；不注入全文，只一句话 |
| **P1** | 建 SelfCard 存储 + 读写 | 方案 1 地基 | 中 | 新存储 `data/memory/self/`（或复用人物卡结构、uid=自标识）；迁移兼容 + 幂等 |
| **P1** | 周小结写回 SelfCard | 方案 3-① | 中 | 复用 `weekly.maybeUpdate` 时机，一周一次，天然幂等 |
| **P2** | SelfCard 作为 L0.5 注入 prompt | 方案 1 闭环 | 中 | 带 `updatedAt`/版本；改完跑金标评测集兜底 |
| **P2** | 日记 chatDigest 改读记忆摘要 | 方案 3-② | 中 | 读人物卡/事件卡摘要，不是原文；注意「按 chat 隔离」不能破 |

**实施要点（通用）**：

1. **一切「人设相关」改动都要过金标评测集**（`tests/persona-eval/`，本次已建）：注入 SelfCard、改抽取提示词、改日记 voice 后，跑一遍通过率不许跌。
2. **SelfCard 是新增存储**，必须做：迁移兼容（旧数据无 SelfCard 不影响启动）、幂等（周小结一天/一周只写一次）、隔离（不违反「按 chat 隔离」，SelfCard 是全局单张还是按 chat 分张要定清楚——建议**全局一张**，因为「她」是跨 chat 同一人）。
3. **注入人设到记忆抽取**要控制长度：抽取是后台但也不是无限预算，压一句话（≤80 字）即可，别把整段 customPrompt 塞进去。
4. **日记写回记忆**要防重复：用 `weekly` 的「一周一次」天然幂等；日记的「今天有感」若要写回，得用 `state.rewrites` 水位去重，别每轮都写。
5. **先 P0 两件，再动 SelfCard**：P0 无新存储、无行为风险，能立刻验证「记忆基调对上人设」「日记像她」；SelfCard 是结构性新增，等 P0 验证了「记忆↔人设」这条链路的方向，再上。

---

## 五、一句话总结

记忆记「对方」、人设写「静态的她」、日记写「B 站的她」，三者缺的是**「她自己的长期记忆」**。补一张 SelfCard 做枢纽：日记/周小结往里沉淀（方案 3），SelfCard 作为动态人设层反哺她的性格（方案 1），人设边界反过来约束记忆抽取的基调（方案 2）——这样「记得住、长得出、有个性」才真正闭环，而不是三个孤岛。
