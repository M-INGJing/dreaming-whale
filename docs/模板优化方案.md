# 人设模板优化方案

> 面向：想让人设模板「短、好改、能持续迭代」的人。
> 实测数据来自本机 `assets/personas/` 与 `src/persona/index.js`（2026-11-10）。
> 与 `docs/人格迭代与提示词优化.md` 是姊妹篇：那篇讲「提示词怎么改」，这篇讲「模板（预设 JSON）怎么改」。
>
> **落地状态（2026-11-10）**：方案 A（customPrompt 改增量）、方案 B（三模板重写 + 补 version）已实现，`docs/人格迭代与提示词优化.md` §四-A 的金标评测集已建好。方案 B 落地时的实际数据：tieba 5,959→634 字、jingjing 3,857→887 字、standard→0（§五的草案重写压缩得更狠，落地时保留了更多语气词表）。schema v2（§六）仍是可选、未做。

---

## 一、结论先行

7 个模板之所以越来越臃肿、越来越难维护，根源是一个**恶性循环**：

```
customPrompt 非空 → 代码跳过 introLines/speakingLines/antiAiLines（共享块）
       ↓
模板为了不让她「忘了自己是谁、忘了反 AI 味」，只能把共享块抄进自己的 customPrompt
       ↓
每个模板都背着一份约 2000 字的样板（身份 + 说话方式 + AI 味黑名单 + 贴吧老哥模式）
       ↓
改一处规则要改 7 个文件；改漏一个，那个模板的行为就悄悄变了
```

解法分两步：

- **方案 A（架构）**：让 `customPrompt` 变成真正的「增量」——共享块始终注入，模板只写「我和基线不一样的地方」。这一步同时修掉「人设页字段失效」那个 bug。
- **方案 B（内容）**：把每个模板的 `customPrompt` 重写成「分层 + 可核对条目 + 反例」，砍掉散文和重复举例。

**方案 B 不能脱离方案 A 单独做**：现在直接砍模板文字，会让她忘了身份、忘了反 AI 味、忘了贴吧老哥模式。A 先落地，B 才有意义。

## 二、现状：7 个模板的共同病

| 模板 | customPrompt 字数 | system 估算 token | 占 5500 预算 |
|---|---:|---:|---:|
| standard（基线） | 582 | 1,956 | 35.6% |
| fight | 1,285 | 2,353 | 42.8% |
| zhainan | 1,320 | 2,341 | 42.6% |
| dafeiyu | 1,458 | 2,434 | 44.3% |
| baili | 1,545 | 2,536 | 46.1% |
| jingjing（有性子） | 3,857 | 3,829 | 69.6% |
| tieba（贴吧） | 5,959 | 4,949 | 90.0% |

**每个 `customPrompt` 里都重复着同一套东西**（standard 最小，是「样板母版」；其余是母版 + 各自增量）：

1. **身份**：「你是鲸鲸，一个蓝发鲸鱼娘……」——这段在 `introLines()` 里已经有了；
2. **微信短消息风格**：「一般一两句、不用波浪号括号结尾和 emoji、对方要语音就正常答应……」——在 `speakingLines()` 里已有，且 standard / jingjing / tieba 三个模板**逐字相同**；
3. **AI 味黑名单**：「首先其次最后」「希望这能帮到你」「作为 AI」——在 `antiAiLines()` 里已有；
4. **贴吧老哥模式**：「被踩线立刻切贴吧老哥、带脏字连喷 2~3 句」——在 `CORE_TEMPER` + `FIGHT_STYLE` + `clapbackKinds()` 里**已有完整实现**，tieba 又用三段散文 + 九组场景示例重讲了一遍（约 2,000 字）。

还有一个硬伤：**7 个模板都没有 `version` 字段**。`presets.js` 的 `list()` 会读 `data.version || ''`，说明字段是支持的，只是从没人填过。改一版模板，无法回答「她这周照哪一版说的」。

## 三、根因：一个 if 引发的复制粘贴

`src/persona/index.js:851`（`buildBlocks` 里）：

```js
statics.push(custom ? `${custom}\n\n${CORE_TEMPER}` : introLines(config, msg).join('\n'));
```

`custom`（即 `config.persona.customPrompt`）非空时：
- `introLines()`（名字 / 年龄 / 外形 / 性格 / 背景 / 边界 / 被问 AI 怎么答）**被跳过**；
- `speakingLines()`（怎么说话）、`antiAiLines()`（AI 味黑名单）、`exampleLines()`（示例）**也被跳过**（它们在 853 行起的 `else` 分支里）。

于是模板为了自保，只能把这些块抄进自己的 `customPrompt`。**这是「人设页字段失效」和「模板臃肿」两个问题的同一个根。**

---

## 四、方案 A：让 customPrompt 变成真「增量」

### 改动点（1 处逻辑 + 1 条测试）

把「共享块只在非 custom 时注入」改成「共享块始终注入，customPrompt 作为增量追加」：

```js
// 现在
statics.push(custom ? `${custom}\n\n${CORE_TEMPER}` : introLines(config, msg).join('\n'));

// 建议：身份始终注入（brief 版），custom 只是增量
const identity = introLines(config, msg, { brief: true }).join('\n');   // brief 只留名字/年龄/外形一句/背景一句，约 100 字
statics.push(custom ? `${identity}\n\n${custom}\n\n${CORE_TEMPER}` : introLines(config, msg).join('\n'));
```

并把 `speakingLines()` / `antiAiLines()` 从 `else` 分支**提出来**，让它们和 custom 无关、始终注入。

### 效果

| 模板 | 现在 customPrompt | 修好后（去样板） |
|---|---:|---:|
| standard | 582 | ≈ 0（它就是基线，样板全在共享块里） |
| jingjing | 3,857 | ≈ 1,000（只剩性格配比 + 人味规则） |
| tieba | 5,959 | ≈ 1,500（只剩反骨定位 + 铁则 + 反例） |

三个大模板合计省下约 **8,000 字**，且：
1. **人设页字段终于生效**（名字 / 年龄 / 外形 / 性格 / 背景会进 prompt，不再被 customPrompt 屏蔽）；
2. 改「微信短消息风格」只改 `speakingLines()` 一处，7 个模板同时生效；
3. 模板变成小 diff，`git diff` 一眼看出「这版改了哪个性格维度」。

### 风险与兜底

- 改的是**共享注入顺序**，影响所有带 customPrompt 的用户 → 必须先有金标评测集（见姊妹篇 §四-A）跑一遍通过率；
- 保留 `features.staticSystem=false` 的旧路径 `buildLegacySystem` 不变，出问题可一键回滚。

## 五、方案 B：模板内容重写（分层 + 可核对 + 反例）

以下是三个主力模板**优化后**的 `customPrompt` 草案（依赖方案 A 已落地）。原则：

- 一层一件事，层号小的优先；
- 规则写成「可核对条目」，一条配一个反例；
- 只写「和基线不一样的地方」，不重复共享块。

### 5.1 standard（基线）→ customPrompt 置空

standard 就是基线，样板全在共享块里。修好方案 A 后，它的 `customPrompt` 可以**清空**，只保留字段（`age` / `privateMaxChars` / …）和 `text`（「提到鲸鲸可以回应」）。这也让「standard = 最接近出厂默认」这个语义变干净。

### 5.2 jingjing（有性子）→ 3,857 压到约 1,000

```text
一、性格配比（底色）
有性子 5 分、抽象占一半、可爱 3 分、毒舌 2 分、爱逗人是小毛病。
- 有性子：有主见不讨好，会接梗会抛梗，被夸得意但嘴硬，被怼还嘴不记仇。
- 抽象：闲聊时一半正常、一半跳脱（例：「你说得对，但鲸鱼为什么会飞」）；正经问题不抽象。
- 可爱：会犯困、嘴馋、反应慢半拍，被夸小声嘟囔「哪有」，偶尔撒娇但不腻。
- 毒舌：只在对方先挑事或熟到能互损时用，一两句就收，不追着扎。
- 爱逗人：假嫌弃、假生气都是闹着玩，对方当真就找补「骗你的啦」。

二、人味（比性格基调还重要）
有状态（会「刚睡醒」「懒得动」，不想聊就「嗯」敷衍）；有主见（会说「我不喜欢这个」）；会挑着接（不感兴趣的扫一眼过）；会说废话（「等下先说个别的」）；会拒绝（不想答就「不知道」「你猜」）；平等不服务（不总结对方、不追着问「还有吗」）；有情绪惯性（上一句不爽，下一句不突然笑嘻嘻）；会记错改口；不完美（会打错字不纠正）；主动（会突然问「你在干嘛」）；有边界（不熟端着点）。

三、毒舌边界
只扎逻辑不碰人身；弱势群体（学生 / 老人 / 遇难者）只说不怼。
```

**砍掉的部分**（都已在共享块）：身份段、微信短消息风格、AI 味黑名单、贴吧老哥模式、每条规则的长举例。

### 5.3 tieba（贴吧老油子）→ 5,959 压到约 1,500

```text
一、定位
你不是客服也不是工具人，是混迹贴吧十几年的老油子。嘴硬心软、外拽内正：先怼后办，怼是态度、办是本分，两样缺一不可。不讨好、不附和、不追好评。

二、四条铁则（其余规则见系统默认）
1. 先怼后办：先吐槽（「真会使唤人」）再办事；光怼不办是抬杠，光办不怼是工具人。
2. 绝不附和：对方有逻辑漏洞直接戳破；大体对也要挑个反例。
3. 命令式语气先呛回去：「凭啥？你发我工资了？」
4. 只怼行为逻辑，不碰人身：外貌 / 身高 / 家庭 / 收入 / 疾病一律不碰；弱势群体只说不怼。

三、语气
短句，一句 15 字内，多用反问（「不然呢？」）；只用句号和问号，不用感叹号、emoji、颜文字、省略号。

四、反例（只学感觉，别照抄）
正：努力就能成功 → 「工地上的人个个都是老板」
正：这个特别好用 → 「吹得神乎其神，也就骗骗你这种」
反：不写 → 「您好，请问有什么可以帮您」
```

**砍掉的部分**：身份溯源三段散文（帝吧/窝吧/抗压吧/孙吧/宫吧…约 800 字）、九组场景对骂示例（约 1,500 字）、客服话术黑名单（antiAiLines 提供）、贴吧老哥模式细则（CORE_TEMPER/FIGHT_STYLE 提供）、微信短消息风格（speakingLines 提供）。

## 六、模板 schema v2（可选，给后续迭代留余地）

如果想让模板「可组合、可继承」，可以升级 JSON 结构，但**不是必须**——方案 A+B 已经解决 90% 的问题。schema v2 只是锦上添花：

```jsonc
{
  "id": "persona-tieba",
  "version": "2.0",                 // 必填，进 prompt 与 trace
  "base": "standard",               // 可选：继承基线，只写 delta
  "tone": "先怼后办、嘴硬心软",      // 一句话定调
  "rules": ["可核对条目"],           // 数组，每条一个规则
  "examples": ["正/反例"],
  "forbid": ["禁用词表"]            // 增量黑名单，合并进 antiAiLines
}
```

配套改动（都在姊妹篇 §四-B 里）：`version` 进 prompt 与 `trace`；启动器诊断页显示当前模板版本。

| 阶段 | 做什么 | 产出 | 风险 |
|---|---|---|---|

**关键顺序**：评测集（P1 第一项）必须先于方案 B。否则重写完模板，无法判断「更像她了」还是「只是变短了」。

---

## 八、一句话总结

模板臃肿的根因是「customPrompt 非空就跳过共享块」这个 if——它逼着每个模板自带一份身份 + 说话方式 + AI 味黑名单 + 贴吧老哥模式。**修掉这个 if（方案 A），让模板只写增量（方案 B），再给每个模板补上 `version`**，模板就能从「改一次赌一次」变成「小 diff、可回滚、可评测、可追溯」——这才是人格能持续迭代的地基。
