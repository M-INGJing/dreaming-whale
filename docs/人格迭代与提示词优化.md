# 人格迭代与提示词优化建议

> 面向：想让鲸鲸「越用越像她」而不是「改一次赌一次」的人。
> 实测数据来自本机 `assets/personas/` 与 `src/persona/index.js`（2026-11-10）。
> 模板（预设 JSON）怎么改，见姊妹篇 `docs/模板优化方案.md`。
>
> **落地状态（2026-11-10）**：本文 §五-1（修字段失效）、§五-4 的去重部分已实现；§四-A（金标评测集）已建在 `tests/persona-eval/`；§四-B（版本号）已打通 config + trace。§四-C/D（漂移监测、调教带证据）仍是建议。

---

## 一、现在的链路

```
assets/personas/*.json         人设预设（id / version / customPrompt / 字数上限…）
        ↓ 导入
config.persona.customPrompt    一段自然语言（最多 6000 字）
config.persona.{name,age,appearance,personality,background}
data/persona.json              「主人调教结果」：stylePreset / styleText / emojiLevel
        ↓
src/persona/index.js
  buildPromptParts()  ── features.staticSystem 开 ──→ buildBlocks()
                      └─ 关（回滚用）──────────────→ buildLegacySystem()
        ├─ static  → system 前缀（可缓存）
        └─ dynamic → 最后一条 user 消息里的「本轮状态」
        ↓
src/memory/format.js           人物卡 / 事件 / 摘要（记忆块，也在 user 消息里）
```

两套渲染路径并存：`buildBlocks`（默认）与 `buildLegacySystem`（`staticSystem=false` 时的回滚路径）。**改文案必须改两处**，否则一关开关行为就变。

## 二、实测：提示词被散文规则撑满了

| 预设 | customPrompt | system 字符 | 估算 token | 占 5500 预算 |
|---|---:|---:|---:|---:|
| persona-standard | 582 | 3,313 | 1,956 | 35.6% |
| persona-fight | 1,285 | 4,016 | 2,353 | 42.8% |
| persona-zhainan | 1,320 | 4,051 | 2,341 | 42.6% |
| persona-dafeiyu | 1,458 | 4,189 | 2,434 | 44.3% |
| persona-baili | 1,545 | 4,276 | 2,536 | 46.1% |
| persona-jingjing | 3,857 | 6,588 | 3,829 | **69.6%** |
| persona-tieba | 5,959 | 8,690 | 4,949 | **90.0%** |

（`node` 实测：`buildSystem()` 输出 → `estimateTokens()`。system 不计入 `dialogueBudget` 裁剪，所以 90% 意味着**每轮输入 ≈ 4,949 + 5,500 ≈ 10.4k token**，成本与延迟都由它决定。）

问题不在「长」，而在**长的部分 90% 是形容词和举例**：
- tieba 版把「先怼后办」这一个规则，用三段散文 + 九组场景示例讲了 2,000 字；
- 「不用 Markdown / 不用『首先其次』」这条规则在 `antiAiLines()`、`customPrompt`、`CORE_TEMPER` **三处重复**；
- 规则之间没有优先级，冲突时靠模型自己权衡 —— 行为不可预测的根源在这里。

## 三、六个结构性问题

### 1. 设置了自定义人设后，人设页的字段全部失效（最该先修）

`src/persona/index.js:851`

```js
statics.push(custom ? `${custom}\n\n${CORE_TEMPER}` : introLines(config, msg).join('\n'));
```

`custom` 非空时，`introLines()` 整段被跳过。而 `introLines` 里装的正是 `name / age / job / appearance / personality / background`、边界、以及「被问是不是 AI 怎么答」。

结果：**用户在「人设」页改外形、性格、年龄，只要 customPrompt 有内容，就一行都不会进 prompt。** 页面上改得动、存得下、看起来生效了，实际没有。

`buildLegacySystem:1033` 是同样的问题（`return custom + ...`，没有 introLines）。

### 2. 预设版本号没有进入 prompt，也没有进入日志

`presets.js` 有 `version` 字段，`config.persona.sourcePreset` 也记了 id，但：
- prompt 里没有任何版本标识；
- `trace`（判定链）只记「为什么回/不回」，不记「用哪版人设」。

出问题时无法回答「她这次是照哪一版说的」。灰色地带的调参只能靠回忆。

### 3. 规则是散文，不是可核对的条目

tieba 版有 10 条硬规则 + 9 组场景，全部是叙述句。模型对「永远不要……」的理解差异极大：
- 「能短就短」→ 模型输出 40 字；
- 「一句 15 字以内」→ 模型输出 12 字。

后者可核对，前者只是氛围。

### 4. 静态 / 动态混了事实与指令

「本轮状态」里既有事实（谁在说话、引用了谁、是否 @ 我），也有指令（这条带表情包、这条用语音）。事实变了不影响缓存，指令变了才需要重排；混在一起后，任何一条指令变化都会让整块尾部重新计算，也让模型分不清「这是背景」还是「这是命令」。

### 5. 情绪/对抗靠关键词触发，容易误伤

`clapbackKinds()` / `fightMode` 依赖词表命中。群里有人说「这天气真垃圾」，不是骂她，但「垃圾」在词表里；现在的做法是靠「是否在跟她说话」二次判定，仍会有边界情况。

### 6. 没有质量回归

`tests/persona.test.js` 断言的是「prompt 里包含某些字样」（例如「包含长度限制」），不是「她的回复像不像她」。改一版 prompt，测试全绿，但可能更不像人了。

## 四、让人格「持续迭代」的四件事

按投入产出排序，前两件是地基。

### A. 金标评测集（最该先做）

```
tests/persona-eval/
  cases.jsonl        40~60 条：{ id, scene, input, expect: { maxChars, forbid:[], requireOneOf:[] } }
  run.js             逐条调 buildSystem → complete() → 规则判分 → 打印通过率
```

判分**不用人评**，只用可编程的检查：
- 长度是否 ≤ `maxChars`；
- 是否命中 AI 味词表（「首先/其次/总的来说/希望这能帮到你」）；
- 是否出现 Markdown 标记；
- 是否复读上一轮（与最近 3 条回复的重合度）；
- 该反问时有没有反问（`requireOneOf` 给几个可接受的句式）。

用法：每改一版 prompt，跑一遍，通过率不能跌。这是唯一能让人放心改 prompt 的机制 —— 否则每次调参都是在赌。

场景建议覆盖：被骂 / 被夸 / 群聊插话 / 群聊里别人对骂 / 正经求助 / 深夜 / 问是不是 AI / 要求发语音 / 要求发图 / 复读陷阱。

### B. 人格版本号贯穿全链路

1. `config.persona` 增加 `personaVersion`（导入预设时写入 `id@version`）；
2. `trace` 每条记录带上 `personaVersion` + `promptHash`（只记哈希，不记正文，符合隐私规范）；
3. 启动器「诊断」页显示当前版本。

有了它，「上周还好好的」才有排查起点。

### C. 人格漂移监测（按天聚合，不需要模型）

数据已经在 `data/memory/chats/*/messages.jsonl`。每天算一次：

| 指标 | 健康区间（参考） | 说明 |
|---|---|---|
| 回复 p50 长度 | 8~35 字 | 变长 = 在写小作文 |
| emoji 率 | 5%~30% | 归零 = 变得干巴 |
| 问句结尾率 | 10%~40% | 过高 = 客服化 |
| AI 味词命中率 | < 2% | 「首先/其次/总的来说」 |
| 与前一条回复的相似度 | < 0.5 | 复读 |

超过区间就在启动器状态页提示一句「她最近说话变长了」，而不是等用户察觉。

### D. 调教结果带上证据

`data/persona.json` 现在只有 `styleText` 一句话。建议每次调教记录「因为哪条消息改的」——只存消息长度、类型、emoji 有无，不存正文。积累几十条后就能回答：「她在我问技术问题时会突然变客服」这种具体倾向，而不是笼统的「再毒舌一点」。

## 五、提示词本身怎么改

### 1. 先修字段失效（P0）

```js
// 现在
statics.push(custom ? `${custom}\n\n${CORE_TEMPER}` : introLines(...).join('\n'));

// 建议：custom 时也拼一段精简的身份
statics.push(custom
  ? `${introLines(config, msg, { brief: true }).join('\n')}\n\n${custom}\n\n${CORE_TEMPER}`
  : introLines(config, msg).join('\n'));
```

`brief: true` 只保留「名字 / 年龄 / 外形一句 / 背景一句」，约 100 字。这样人设页的字段至少不会完全失效。

### 2. 分层 + 优先级，替代平铺

```
【第 1 层 · 身份】你是谁、多大、长什么样（≤150 字）
【第 2 层 · 硬边界】违法、人身攻击、未成年（≤80 字，不可协商）
【第 3 层 · 说话方式】句长、标点、颜文字、口头禅（≤250 字）
【第 4 层 · 场景规则】群聊看人下菜、被骂怎么回（≤200 字）
【第 5 层 · 本轮状态】谁在说话、引用了谁、这条要不要带图（动态）
冲突时：层号小的优先。
```

现在这些内容是平铺的，模型只能按「越靠后越重要」的隐式规律猜。

### 3. 规则写成「可核对的条目 + 一组正反例」

| 现在的写法 | 建议的写法 |
|---|---|
| 能短就短，别写小作文 | 一条回复 ≤ 2 句；超过 30 字要能删掉一半 |
| 不要用「首先其次」 | 禁用词：首先 / 其次 / 总的来说 / 希望这能帮到你（命中即失败） |
| 像群里熟人 | 正例：「啊？你认真的」 反例：「这个问题很有意思，让我来分析一下」 |

一条规则配一个反例，比三段形容词管用——反例给了模型明确的「不要往这边走」。

### 4. 去重 + 预算化

- 「不用 Markdown」「不用首先其次」现在三处重复，合并成一处，其余段引用编号；
- 给每段设 token 上限，超了自动截断/压缩。目标：tieba 版从 4,949 压到 **3,000 以内**（约 -40%），行为不变。

### 5. 事实与指令分开

```
【本轮事实】当前发言人、引用对象、@ 了谁、群里有几个人
【本轮指令】这条带表情包 / 这条用语音 / 这条不接话
```

事实变化 → 只影响事实块；指令变化 → 只影响指令块。两者都放尾部，但不要混成一段。

### 6. few-shot 用真实对话，不用手写

`exampleLines()` 现在是 6 条手写示例。更好的来源：从 `messages.jsonl` 里挑主人**没有纠正过**的回复（回复后 3 条内无「不是」「别这样」「重新说」），脱敏后作为示例池，按场景随机抽 3 条。这批示例天然符合当前人设，且会随使用自动更新。

## 六、建议的落地顺序

| 阶段 | 做什么 | 产出 | 风险 |
|---|---|---|---|
| P0 | 修 `customPrompt` 屏蔽 `introLines` 的问题 | 2 行改动 + 1 条测试 | 低（只影响有 customPrompt 的用户） |
| P0 | 人设版本号进 config + trace | 3 个文件 | 低 |
| P1 | 建 40 条金标评测集 + 规则判分脚本 | `tests/persona-eval/` | 低（纯新增） |
| P1 | 提示词分层 + 去重 + 预算化 | `src/persona/index.js` 重构 | 中（要跑评测集兜底） |
| P2 | 漂移监测（按天统计） | `src/services/` 新增 | 中 |
| P2 | few-shot 从真实对话抽样 | 依赖标注流程 | 中 |

**建议先做 P0 两件**：它们各自很小，但一个是「用户改了没效果」的真实 bug，一个是「以后改不动」的根因。P1 的评测集是后续所有调参的前提——没有它，P1 的第二项不该动。

## 七、模板怎么改（补充）

模板优化单独成篇，见 `docs/模板优化方案.md`。核心结论：

- **根因**：`customPrompt` 非空时，代码跳过 `introLines` / `speakingLines` / `antiAiLines`，逼着每个模板把身份 + 说话方式 + AI 味黑名单 + 贴吧老哥模式抄进自己的 `customPrompt`。
- **方案 A**：让 customPrompt 变成真「增量」，共享块始终注入 → tieba 5,959 压到约 1,500、jingjing 3,857 压到约 1,000，顺带修掉「人设页字段失效」。
- **方案 B**：三个主力模板按「分层 + 可核对条目 + 反例」重写。
- **7 个模板都没有 `version` 字段**，配合本文 §四-B 一起补上。
