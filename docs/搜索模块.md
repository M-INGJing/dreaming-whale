# 搜索模块

鲸鲸的联网搜索分两条路：

- **通用网页搜索**：由 DeepSeek 官方托管（`deepseek_web_search` 工具）。模型判断需要时自动搜索并附引用，客户端不写工具调用循环。
- **天气 / 热搜**：保留专用路由（Open-Meteo、微博 / B 站 / 头条热榜），精度比通用搜索高。

聊天流程仍通过 `src/services/search.js` 的 `search()` 获取天气 / 热搜证据；通用网页搜索不再走这里，改由 `src/llm/client.js` 在调模型时声明工具。

## 官方托管搜索（deepseek_web_search）

### 使用方法

- 开关 `websearch.native`（默认 `true`，即开启）。设 `false` 则不声明该工具，回到「不联网」。
- 仅 `deepseek-flash`（DeepSeek-V4.1-Flash）支持；其它模型或服务商自动不声明，不会报错。
- 打开后**无需任何搜索 API Key**：搜索由 DeepSeek 服务端完成，也不用自建抓取。

### 工作原理

调 `/chat/completions` 时在 `tools` 里声明 `{ "type": "deepseek_web_search" }`。模型判断需要搜索时，服务端自动检索、把结果和引用拼进上下文，返回的 `content` 直接就是带引用的答案。

- 是否搜索由模型自判，**不能用 `tool_choice` 强制指定**（会返回 400）。
- 声明该工具时 `temperature` 等参数由服务端接管，客户端不再发送。
- 路由判断、连接测试、token 计数不声明工具，不产生搜索。
- 通用网页搜索因此不再有「本地抓取后注入提示词」的 `webText` 证据；天气 / 热搜仍会注入。

### 费用（重要）

- 搜索**按「成功的次数」计费，不是按 token**：搜索（文字 / 图片）5 元 / 千次，网页抓取（读链接）5 元 / 千次。
- 只算 HTTP 200 且真拿到结果；失败、无结果、超时不计费；一次返回几条结果不影响单价。
- 一次回答可能触发多次搜索（模型自己搜几个关键词就计几次），响应的 `server_tool_use` 字段返回实际次数。
- 搜索与读链接是两条独立计费记录。

### 已知限制

- 官方未公布引用格式的文档；目前 `content` 里带 `[数字]` 标记，但引用链接列表在响应的 `server_tool_calls`/`citations` 字段里，尚未透出到回复。
- 需要限定搜索来源（域名白名单等）时，官方托管搜索不支持，需改用独立 Search / Fetch 接口。

## 天气 / 热搜（专用路由，保留）

1. 常规天气优先 Open-Meteo，只用于当前及今明两天常规天气。空气质量、台风路径、远期 / 历史或明确其他日期的请求不拿天气冒充，交给官方托管搜索。
2. 平台热榜优先对应接口（微博 / B 站 / 头条）。泛热点新闻走热榜，具体主题新闻交给官方托管搜索。
3. 城市优先级：本句明确地点 > 配置城市 > IP 推测；显式地点无法解析时保留原问题，不改查默认城市。

## 分层

- `src/llm/client.js`：官方托管搜索的声明（`canNativeSearch()` 判定 + `buildPayload` 注入 `tools`）。
- `src/services/search.js`：天气 / 热搜的路由、预算与回退；通用网页分支返回 `skipped('native_search')`。
- `src/core/search/policy.js`：本地路由兜底、平台约束、天气能力范围。
- `src/core/search/quality.js`：查询清洗、相关性等纯函数。
- `src/core/search/result.js`：统一结果协议和最终资料格式化。
- `src/adapters/searchRouter.js`：模型 JSON 路由；完整意图为 `kind/query/site/city/fresh/timeRange`。
- `src/adapters/search/`：传输、热榜、天气和公开数据缓存。
- `src/adapters/websearch.js`：天气 / 热搜的兼容门面；定位服务仍可调用 `ipCity/geocodeCity`。

## 回退与时限

1. `semanticRoute` 未配置时只对疑似事实问题调用模型；`true` 每句调用，`false` 只走本地规则。
2. 明确的 `need:false` 跳过查询；路由失败或旧路由缺少分类字段时由本地策略兜底。
3. 天气 / 热榜失败后不再回退自建抓取，统一交给官方托管搜索（`skipped('native_search')`）。
4. 全过程共用 `websearch.timeoutMs`，默认 8 秒。语义路由最多 2 秒；天气 / 热榜最多使用路由后剩余预算的 60%。
5. 所有网络请求支持 `AbortSignal`、绝对时限、重定向次数和响应体大小限制。

## 缓存与诊断

- 热榜缓存 60 秒；地理编码和 IP 城市缓存 6 小时。仅内存缓存，容量有限，不缓存失败或空结果。
- 相同公开数据请求合并；每个等待者的预算和取消独立，最后一位退出才取消共享请求。
- `trace` 只记录来源、计数、状态、耗时与安全错误摘要，不记录 `items`、问题正文或历史内容。
- 错误摘要通过 `describeError` 生成；外部异常消息可能包含 URL 或响应正文，先转结构化错误再记录。
