# 表情包收藏计划（别人发的 → 自己用）

> 状态：**规划中**，先定方案再写代码。
> 目标：私聊/群里别人发来的表情包，自动存进鲸鲸自己的图库，按「语境 + 画面内容」分类；重复的不存。

---

## 1. 范围与边界

**做**

- 只收**表情包消息**（微信 `type=47` 的 emoji）；普通照片、截图、长图**不**进图库。
- 来源：私聊 + 群聊，但**只收别人发的**（不收鲸鲸自己发的、不收回声）。
- 存进现有图库 `data/stickers/<分类>/`，直接参与现有「发图」流程（`[[sticker:分类]]`）。
- 分类：内置三类（傲娇 / 炸毛 / 开心）+ 自定义分类；拿不准就进「待定」，不硬猜。
- 去重：内容哈希 + 感知哈希两层；重复的只记「又见到一次」，不重复落盘。

**不做（第一版）**

- 不做以图搜图 / 向量检索（成本高，收益在几十张以内不明显）。
- 不做自动删除旧图（人工在启动器里删）。
- 不收普通图片里的「像表情包的图」（误收照片的代价比漏收大）。
- 不改现有发送链路（发送端只多一个「待定」分类要跳过）。

| 已有 | 位置 | 对本功能的意义 |
|---|---|---|
| 表情包单独识别 | `bridge/receiver_mixin.py#describe_emoji` + `bridge/emoji_vision.py` | 已经能把 emoji 消息解出帧/预览并转 PNG，**字节现成** |

| 图库维护 | `src/services/stickerService.js` + `src/services/stickers.js` | 已有启动迁移/去重；新收藏要走同一套命名与扩展名规则 |
| 发送端 | 模型用 `[[sticker:分类]]` 指定分类 | 新分类/待定分类要能被 `pick` 识别或跳过 |

**现状缺口**

- 收消息时只把表情「描述成文字」喂给模型，**没有落盘**。
- 图库没有内容哈希索引；现有「去重」是按文件名/目录做迁移，不是按内容。
- 没有任何「这张图从哪个群、配什么话」的上下文记录。

## 3. 关键问题一：怎么保存

### 3.1 字节从哪来（三条路，选 A）

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A. 桥接缓存原图（推荐）** | `describe_emoji` 里已有解码后的 PNG（或可再取原图）；顺手把字节 POST 给内核 | 不重复下载；但要控制请求体大小与并发 |
| B. 内核按 msgId 回头下载 | 内核拿到 msgId 再找桥接要图 | 多一次往返，桥接要暴露下载接口（复杂） |
| C. 只存预览帧 | 把多帧预览拼图存下来 | 丢动画、丢透明通道，**不推荐** |

落地细节：

- 优先保存**原始格式**（GIF 保动画、PNG 保透明）；拿不到原图时退回 `load_preview` 的单帧 PNG。
- 单张上限 2 MB（现有 `/api/vision` 与 `readBody` 都是 2 MB，超过直接跳过并记一条事件）。
- 传输用 base64 JSON（沿用现有 `/api/vision` 风格），不做 multipart。

### 3.2 落盘位置与命名

```
data/stickers/
  傲娇/ 炸毛/ 开心/ <自定义>/
  待定/                      ← 低置信度先放这里，等人工确认
  index.json                 ← 收藏索引（唯一真相）
  .tmp/                      ← 先写临时文件再 rename
```

- 文件名：`<sha256 前 12 位>.<ext>`（内容寻址，天然不会重名）。
- 写盘：`.tmp` → `fs.rename`，避免半张图。
- 索引 `index.json` 记录（不存聊天正文）：

```jsonc
{
  "version": 1,
  "items": {
    "sha256:ab12…": {
      "file": "开心/ab12cd34ef56.gif",
      "dhash": "9f3c…",            // 64 位十六进制
      "category": "开心",
      "confidence": 0.82,
      "tags": ["猫", "大笑"],
      "description": "一只猫笑得打滚（≤80 字）",
      "source": { "chatType": "group", "chatIdHash": "…", "sender": "昵称" },
      "addedAt": 1794…, "seen": 3, "lastSeenAt": 1794…
    }
  },
  "pending": ["sha256:…"]        // 待定，人工处理
}
```

- `chatIdHash` 只存哈希（防泄露群号）；`sender` 存昵称（可选，关掉也能用）。
- 索引按 `<sha256>` 主键，天然幂等：同一张图重复提交只会更新 `seen/lastSeenAt`。

## 4. 关键问题二：怎么判定重复

分三层，**第一层就够挡住 95%**，后两层防「同一张图被转过一次、压过、改过尺寸」。

| 层 | 算法 | 命中条件 | 成本 |
|---|---|---|---|
| 1. 字节完全相同 | `sha256(bytes)` | 相等 | 极低（必做） |
| 2. 视觉近似 | 64 位 dHash（9×8 灰度）+ 宽高比 | 汉明距离 ≤ 6 且宽高比差 ≤ 15% | 低（纯 JS，几十微秒） |
| 3. 语义重复（可选） | 用视觉描述做归一化后字符串比较 | 描述完全相同且同分类 | 低（不额外调模型） |

补充规则：

- **同一天同一来源反复刷同一张**：命中第 1 层，只 `seen++`，不写盘、不重复分类。
- **近似但不同**（例如原图 vs 加了白边）：`dhash ≤ 6` 视为重复，保留**分辨率更高/文件更大**的那张；如果新图更清晰，替换文件并更新索引（旧文件删掉）。
- **动画 vs 静态**：同一组画面但一个是 GIF、一个是 PNG → 视为不同（动画信息有价值），但两者 dHash 相同，需要**格式也参与判重**：`(sha256)` 不同 + `dhash` 相同 + 格式不同 → 保留两张但只对同格式去重。
- **阈值可配**：`stickers.collect.dhashDistance`（默认 6）、`stickers.collect.sameFormatOnly`（默认 true）。
- **索引缺失/损坏**：启动时重建索引（扫描目录、算 sha256 + dhash），不阻塞聊天。

## 5. 分类：画面内容 + 语境

### 5.1 输入

一次分类需要三样东西：

1. **画面**：视觉模型描述（复用 `/api/vision`，提示词固定为「描述主体/表情/动作/文字，不编造」）；
2. **语境**：该会话最近 3~5 条消息（只取文本，≤200 字）、发送者、群/私聊、是否在回复某条；
3. **图库现状**：现有分类列表 + 每类最近 3 个描述（让模型知道「开心」长什么样，避免分类漂移）。

### 5.2 输出（一次 LLM 调用，JSON）

```json
{"category":"开心","confidence":0.82,"tags":["猫","大笑"],"reason":"猫笑到打滚，群里在接梗"}
```

- `category` 必须来自现有分类枚举；不确定时返回 `待定`。
- 置信度 < `0.6` → 直接进「待定」，不写正式分类。
- `tags` 最多 4 个，只用于展示/检索，不参与发送。
- 解析失败/模型超时 → 进「待定」（绝不猜）。

### 5.3 待定队列

- `data/stickers/待定/` 只是暂存目录；索引里 `pending` 标记。
- 启动器「表情包」页展示待定列表（缩略图 + 描述 + 建议分类 + 语境摘要），可一键「归到某类」或「删除」。
- 待定不参与发送；超过 7 天未处理可自动删除（可配）。

### 5.4 为什么不只用语境

群里一句「哈哈哈」配一张猫图，单看语境会全归「开心」；只看图又会把「阴阳怪气」归成「开心」。两个信号一起用，再留「待定」兜底，比单一信号稳。

## 6. 流程（时序）

```
微信 emoji 消息
  └─ bridge.describe_emoji（已有）
       ├─ 视觉描述 → 照旧喂给模型
       └─ 若 stickers.collect.enabled：
            POST /api/stickers/collect
              { image(base64), mime, chatType, chatId, sender, recent:["…"], msgId }
内核 collect：
  1) 限流/开关/大小/扩展名校验
  2) sha256 → 命中索引？ → seen++，返回 duplicate（不落盘）
  3) dHash → 近似命中？ → 记 seen，必要时替换更清晰版本，返回 duplicate
  4) 落盘到 待定/（先不分类），入队分类任务
  5) 异步 worker（并发 1）：
       vision 描述 → LLM 分类（带语境）→ 置信度够 → 移到 <分类>/，更新索引
                                               └─ 不够 → 留在 待定/
```

- `collect` 接口**只做去重与落盘**，立即返回（≤50ms），分类走后台队列，桥接不用等。
- 分类失败不影响聊天；队列有上限（默认 50），满了丢最旧的并记事件。
- 所有失败只记结构信息（大小、哈希前缀、错误码），不记图片内容。

## 7. 配置

```jsonc
"stickers": {
  "collect": {
    "enabled": true,            // 总闸（还需要 features.stickers 打开）
    "fromGroups": true,
    "fromPrivate": true,
    "skipFromMaster": true,     // 不收主人自己发的（避免把鲸鲸的图又收回来）
    "maxPerDay": 30,
    "maxFileBytes": 2097152,
    "dhashDistance": 6,
    "sameFormatOnly": true,
    "minConfidence": 0.6,
    "pendingTtlDays": 7
  }
}
```

- 限额按「新增收藏」算，重复命中不占额度。
- 单日超限：只 `seen++`，不落盘，日志一行「收藏已满」。

## 8. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/stickers/collect` | 桥接提交一张候选（去重+落盘，快速返回） |
| GET | `/api/stickers/pending` | 待定列表（缩略图可走 `/api/stickers/thumb`） |
| POST | `/api/stickers/resolve` | `{sha256, category}` 或 `{sha256, action:"delete"}` |
| GET | `/api/stickers/collect/status` | 收藏计数、今日新增、队列长度 |

（现有 `/api/stickers/*` 已有状态/上传/删除，新接口挂在同一 router，不新开页面。）

## 12. 待确认的取舍（写代码前拍板）

1. **开关默认值**：`collect.enabled` 默认 **false** 还是 **true**？（建议 false，用户显式打开再收）
2. **是否收主人的图**：`skipFromMaster` 默认 **true**（建议）。
3. **近重复阈值**：`dhashDistance=6` 偏保守；同一张图被转压过通常 ≤4，想更严可调 4。
4. **待定 7 天自动删**是否可接受？还是永久保留等人工？
5. **分类来源**：只用内置三类 + 已有自定义分类，还是要允许模型「提议新分类」？（建议先不提议，避免分类爆炸）
