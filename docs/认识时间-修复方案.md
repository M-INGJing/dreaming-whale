# 「我们认识多久了」瞎编 —— 修复方案

> 现象：问她「我们认识多久了 / 什么时候认识的」，她凭空编一个日期或年头。
> 状态：**方案，未实施**。依据：`src/memory/chatStore.js`、`src/memory/personCard.js`、`src/memory/store.js`、`src/memory/format.js`、`src/persona/index.js`（2026-11-14）。

---

## 1. 根因：数据一直在，只是从没进提示词

系统**早就记了**她什么时候认识对方：

- `chat.createdAt` —— 会话（聊天）首次创建时间，存在每个会话的 `meta.json`（`chatStore.js:159/287/550`）；
- `personCard.firstSeenAt` —— 人物卡上「第一次见到这个人」的时间（`personCard.js:95`），私聊里就是对方、群聊里是当前说话人。

问题出在**渲染层**：`src/memory/format.js` 的 `buildMemoryBlock`（`store.js:395` 调用）只把人物卡渲染成「性格 / 偏好 / 没聊完」三行，**从没把 `firstSeenAt` 渲染进 prompt**。于是她被问「认识多久」时，脑子里关于这件事的信息是**零**——语言模型在零依据下，最自然的行为就是编一个听起来合理的日期。

同样的根因还波及「我们什么时候开始聊的」「你第一次见我是啥时候」这类同族问题。

---

## 2. 修复：把「第一次聊」这个事实喂进去 + 加护栏

### 改动 1：渲染一行「第一次聊」（`format.js` + `store.js`）

`buildMemoryBlock` 的 `【这个聊天里的 TA】` 段加一行：

```
【这个聊天里的 TA】
- 第一次聊：2026-11-07（认识约 7 天）
- 性格：…
- 偏好：…
```

- 时间取 `card.firstSeenAt`（人，优先），缺则 `chat.createdAt`（会话，兜底）；
- 需要把 `createdAt` 从 `store.js:395` 传入 `buildMemoryBlock`（`chat` 就在作用域里，一行的事）；
- 用「约 N 天 / N 个月 / N 年」这种**人话**而不是裸时间戳，模型答得才自然；小于 1 天就写「今天刚认识」；
- 一行很短，走记忆块现有预算裁剪，不单独占配额。

### 改动 2：护栏（`persona/index.js`）

在 `introLines`（默认人设）和 `identityBriefLines`（自定义人设）里，跟「最新/价格别拿训练数据」「别编版本号」并排放一条：

> 被问「我们认识多久 / 什么时候认识的 / 第一次见我是啥时候」：只能根据上面「第一次聊」那一行来答；有就照实说（可以说「大概是 X 月 X 日开始聊的」），没有就说「具体哪天记不清了，但印象里是 X 前后」，**绝不编一个精确日期、年头或故事**。

要点：**用行为描述，不用否定式**。实测「不要编日期」这种否定式会被模型念出来当开头（项目里已踩过同样的坑，见 `introLines` 里「别报型号」那条的注释）。

### 改动 3：测试

- `tests/memory-format.test.js`（或新建）：给一张带 `firstSeenAt` 的卡，断言 `buildMemoryBlock` 输出含「第一次聊」和「约」；
- `tests/persona.test.js`：断言默认与自定义人设的 prompt 都含「认识多久」护栏句。

---

## 3. 边界与注意

1. **群聊的语义**：`firstSeenAt` 是「这个说话人」第一次被见到的时间，群聊本就只注入当前说话人的卡，所以「认识多久」在群聊里答的是「认识**这个说话人**多久」，语义正确。
2. **私聊 = 对方，群聊 = 进群时间有差异**：`chat.createdAt` 在私聊 ≈ 认识对方的时间；群聊里是「进群时间」而非「认识某个人」。所以优先 `firstSeenAt`（人），`createdAt` 只在卡上没有 `firstSeenAt` 时兜底。
3. **迁移/旧数据**：`migrate.js:175` 会从旧格式回填 `firstSeenAt`，所以老记忆也能吃上这行；没有 `firstSeenAt` 且没有 `createdAt`（理论上不会）时，宁可渲染「认识时间记不清」，也不要填 `Date.now()` 假装今天认识——那会变成「每天都是刚认识」。
4. **不新增存储**：纯读已有字段，零迁移风险。
5. **预算**：这行固定 ≤ 30 字，走现有裁剪链，不会挤占人物卡配额。
