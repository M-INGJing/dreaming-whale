# 鲸鲸「不懂现实世界、不会用搜索结果」优化方案

> 面向：让她能回答「现在/最新/赛事结果」这类实时问题，而不是拿训练数据瞎答、或甩一句「我去查一下」。
> 状态：**方案，未实施**。依据：`src/services/search.js`、`src/adapters/search/*`、`src/pipeline/chat.js`、`src/persona/index.js`、`src/core/search/policy.js`（2026-11-14）。

---

## 0. 结论先行：搜索是「单次、尽力而为、本机网络下必然失败」

先纠正一个误会：**联网搜索不是没做，是早就接进了聊天管线**。

- 消息进来、判定该回之后，`src/pipeline/chat.js:762` 会调一次 `searchService.search()`；
- 一个 2 秒的 LLM「路由」先判断这句话要不要联网（`searchRouter.js`），再走关键词兜底；
- 结果写进 `msg.webText`，由 `persona/index.js` 的 `webSearchContext()` 注入提示词，或注入一句「本次查询失败」的诚实说明。

问题不在「没有搜索」，在于下面三点叠加，让用户感觉「她根本不会搜」：

1. **搜索后端是「抓 Bing/360 网页」，且不认系统代理** → 本机网络下每次都失败；
2. **搜索是「回复前的一次尝试」，没有「搜完再答」的第二步** → 失败了只能拿训练数据硬编；
3. **路由/关键词对「赛事/电竞/时政」这类当前事实覆盖不全** → 有些问题压根不触发搜索。

---

## 1. 根因拆解（按严重度排序）

### 根因 A：搜索 HTTP 客户端不认代理，本机必然超时（最致命）

`src/adapters/search/transport.js:61` 用的是 Node 原生 `https.get()`：

```js
req = https.get(parsed.toString(), { headers: { 'User-Agent': ... } }, ...);
```

Node 的 `https.get` **不会自动读 `HTTP_PROXY` / `HTTPS_PROXY`**（和 curl / git 不一样）。也就是说：本机明明挂着代理（`127.0.0.1:5217`），联网搜索却**直连** `cn.bing.com` / `www.so.com`。

而本机到外部站点的直连是被阻断/抖动的（实测 `github.com` 直连失败、代理返 502）。结果就是：`cn.bing.com`、`so.com` 请求在 `websearch.timeoutMs`（默认 8000ms）内永远拿不到，返回 `failed` / `deadline_exceeded`。

→ 搜索在**这台机器上百分之百失败**，她自然「没查到」，只能凭训练数据瞎说或甩「我去查一下」。

### 根因 B：失败后没有「搜完再答」的第二步，模型只能硬编

搜索是生成**之前**的一次性动作。失败时，`webSearchContext()` 注入的是「本次查询失败，不要编造…」这段诚实说明，但**没有第二次动作**。模型面对「S 赛决赛谁打谁」这种它不知道、又没资料的问题，最自然的反应就是编一句「我去查一下」——而这句话背后没有任何真的会去查的机制，于是用户看到的就是「说了去查、却不回复」。

### 根因 C：路由/关键词对「赛事、电竞、时政」覆盖不全

`src/core/search/policy.js` 的关键词表 `KEYWORDS` 和 `FACT` 正则，覆盖的是「天气/价格/型号/热搜」这类，**没有**「决赛、冠军、比分、夺冠、S赛、世界赛、谁赢了、战报、排名榜」等赛事词。`FACT` 里的 `谁` 只在 `是谁` 这个组合里，裸的「谁打谁」命中不了。

所以「26年英雄联盟S赛决赛谁打谁」这类问题，关键词兜底抓不住，只能赌那个 2 秒 LLM 路由能判对——而路由也可能超时或判成 `need:false`。

### 根因 D：预算紧、无重试、无 API 兜底

- 总预算 `timeoutMs` 默认 8000ms，路由单独占 2000ms，抓 Bing + 备选 360 全在剩余几秒里完成；
- 抓取被搜索引擎反爬（`blocked`/验证码）时没有替代路径；
- 没有「失败后换更宽松的查询再试一次」；
- 全程无 API Key 依赖，但也没有「配个搜索 API 当兜底」的选项。

## 2. 优化方案（按优先级）

### P0-1：让搜索 HTTP 客户端支持代理（恢复搜索的第一步）

- 在 `transport.getText()` 里支持代理：读 `websearch.proxy`（新增配置），留空时回落到系统 `HTTPS_PROXY`；
- Node 无依赖做 HTTPS 代理要用 CONNECT 隧道，或直接换成 `http.request` + `CONNECT` 手写隧道（项目零依赖，不能引 `proxy-agent`/`https-proxy-agent`，但 30 行 CONNECT 隧道可自实现）；
- 配置示例补 `websearch.proxy`，说明「留空 = 直连；填 `http://127.0.0.1:5217` 走本机代理」。

**效果**：本机这类「代理能通、直连被墙」的环境，搜索立刻恢复。

### P0-2：增加可配置的「搜索 API」供应商，抓取被墙也能用

抓 Bing/360 网页本质脆弱（反爬、改版、被墙）。加一条 API 兜底：

- 新增 `websearch.provider`：`scrape`（现状，默认）/ `api`；
- `api` 模式走一个带 Key 的搜索接口（Serper.dev / Bing Web Search / 博查 / Tavily 选一，推荐先接 **Bing Web Search**：国内可用、结果干净、按次付费），`websearch.apiKey` 新配置；
- `searchResult()` 里加一个 `api` provider，与 `bing`/`so360` 并列，按 provider 顺序回退（`api` 失败再抓取，或反之，可配）。

**效果**：反爬/被墙都不再是死路，付费额度小（每天几十次查询足够）。

### P1-1：关键词/FACT 门补「赛事、电竞、时政、榜单」词

在 `policy.js` 的 `KEYWORDS` / `FACT` 里补：`决赛|冠军|亚军|比分|夺冠|淘汰|小组赛|淘汰赛|总决赛|世界赛|S赛|春季赛|夏季赛|谁赢了|战报|对阵|赛程|积分榜|排名|拿下|夺冠热门|发布会|上市|首发|当选|任命|去世|逝世|结婚|官宣`。

**效果**：明显指向「当前事实」的问题不依赖 LLM 路由的运气，关键词直接命中进搜索。

### P1-2：路由对「当前事件」强制 `fresh=strict` + 自动补年份

- `searchRouter.js` 的 SYSTEM 已写「不要自己加年份，除非用户原话提到」。但用户说「26年/今年」时，查询词里没年份，Bing 可能返回旧赛事；
- 改法：路由解析后，若 `fresh=strict` 且 query 里没有 4 位年份、而用户原话含「今年/这年/2x年」或问的是「决赛/冠军/结果」，就把年份补进 query（如 `2026 英雄联盟 S赛 决赛 对阵`）。

**效果**：搜出来的结果命中当前这一届，而不是几年前的旧赛。

### P2-1：「搜不到」也能给出一条真正可用的出路（两步动作）

现在失败 = 一句「我去查一下」的空话。改成两种可选：

- **方案 A（推荐，最小改动）**：失败/空结果时，`webSearchContext` 的文案从「说明未能确认」升级为「诚实说没查到 + 明确告诉对方可以回一句『搜一下 X』再查一次」。同时在内核加一个 `/搜一下 <词>` 或 `/search <词>` 的管理口令，触发一次**长预算**（如 15000ms）、放宽相关性、可指定 provider 的强制搜索并回结果。
- **方案 B（彻底）**：把搜索做成 `[[cap:search]]` 能力，她能自己决定「先回一句『我去查』、查完再补一条」。但能力机制是异步的，涉及跨轮回复，复杂度高，不建议首发。

**效果**：用户有了一条真实可用的「再查」路径，而不是看她演。

### P2-2：预算与重试

- `websearch.timeoutMs` 默认 8000 偏紧，建议 12000；路由 2000ms 不动（它是门槛，不是主查）；
- `searchResult()` 失败且还有预算时，用「去掉停用词/换 queryTokens」重试一次（逻辑已部分存在，补一个「失败重试」分支即可）。

### P3：可观测

- 日志里已有 `[search] stage=…` 和 `decision/complete` 阶段，够排障；
- 再补一个调试出口：`/api/debug/prompt` 返回里带上 `webSearchStatus` / `webSearchReason` / 注入的 webText 长度，出问题时不用翻日志就能看到「是路由没触发、还是触发后失败、还是搜到但被裁掉」。

## 3. 落地顺序建议

| 批次 | 内容 | 风险 | 收益 |
|---|---|---|---|
| **P0** | 代理支持 + API 供应商兜底 | 中（自实现 CONNECT 隧道要测；新配置要进 schema） | 让搜索**真的能通**，是所有后续的前提 |
| **P1** | 关键词补赛事词 + 补年份 | 低（纯规则/提示词） | 「谁打谁」这类问题稳定触发且搜得准 |
| **P2** | 「搜一下」口令 / 能力 + 预算重试 | 中（新交互路径） | 失败时有真实出路 |
| **P3** | 调试出口暴露搜索状态 | 低 | 排障 |

P0 是地基：**不先让搜索通，P1/P2 做得再漂亮她也还是「没查到」**。
